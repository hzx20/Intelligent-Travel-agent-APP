# 旅行编辑、预订与账本的网络恢复验收

frontend目录运行：

```powershell
npm run test:e2e:network
```

继承账号套件的独立Edge和真实Uvicorn夹具：127.0.0.1:5264/travel/代理到18963；使用临时磁盘库、合成账号和随机JWT，外部服务钥匙为空，不访问现有业务库。不与账号套件同时运行，因为它们使用相同端口。

桌面1280×900与手机视口390×844各五项，共10项：

1. 使用浏览器真实offline状态阻止安排保存；输入保留、表单解锁，恢复网络后手动重试，后台仅一条安排。
2. 预订POST先通过route.fetch送达真实后端并提交，再故意中断浏览器响应。核对按钮读取最新旅行与记录，保留表单；重试继续使用首次提交版本，真实后端拒绝重复新增，记录数仍为一。
3. 账本使用同样的已提交/丢失响应流程，金额保留且支出不会重复记入。
4. 安排请求在转发前停滞，等待实际默认15秒超时，不使用虚拟时钟；超时后恢复输入和保存按钮，没有自动重试。第一次没有送达后端，手动重试后仅一条安排。
5. 预订GET返回一次受控503；读取重试恢复已有记录，不清空独立表单。

普通API默认15秒，调用方显式的长模型/OCR等待时间继续生效；显式timeout:0仍可关闭等待上限。照片请求保留原30秒上限。写入的断连、超时、损坏响应及5xx会提示结果待核对，不能用失败响应断言后端没有提交。

预订和账本创建表单在第一次提交时固定版本；核对后即使页面版本更新，原表单仍沿用旧版本，避免把不确定的旧操作当作新操作新增。用户确认已有记录后可清空表单，重新填写才开始新的一次记录。编辑记录继续沿用开始编辑时的版本。

这使用已有服务端版本比较与交换，不是通用幂等键，也不是自动恢复或撤回所有操作。旅行创建、分享链接、其他旧页面写入和复杂故障仍需后续单独检查；生产网络、供应商、真实账号和实际手机设备也未由本套件证明。

结果在Git忽略的 `frontend/playwright-results/network`。测试结束自动关闭后端/Vite/独立浏览器并清理临时目录。使用方式和Python/Edge要求同 `../account-sharing/README.md`。
