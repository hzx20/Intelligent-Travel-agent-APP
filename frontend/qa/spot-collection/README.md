# 景点加入旅行与详情故障保护

frontend运行`npm run test:e2e:spot-collection`。桌面1280×900、手机视口390×844各十项，共20项。独立Edge、真实FastAPI、临时磁盘SQLite、合成账号，阻止非本机请求，不等于真实手机/生产账号验收。

本套件与spot-writes/accounts/profile/guide-detail/guide-editor/sharing/network/creation共用5264/18963，必须串行。默认工作区上级`.venv-analysis`和已安装Edge，可设置TRAVEL_E2E_PYTHON。输出在Git忽略的playwright-results/spot-collection，可能含合成凭证，不发布；每次定向运行会重建该目录，完整套件才生成全部截图。

## 隔离夹具

配置metadata.seedSpots=true时，共用启动器改用spot-backend.py。脚本只接受生成的travel-browser-accounts-*目录下绝对数据路径，拒绝已有app.db和外部地图/模型密钥，再预置两个无坐标、无图片的人工景点。第一个POI标识为空，证明防重复不是依赖POI去重。其他套件保留原uvicorn启动方式；原模式注册/重载两项烟测通过。没有初始化工作区业务库或访问外部供应商。

## 页面覆盖

1. 原生模态Tab焦点、Esc恢复入口，正常加入账号旅行只保存一条。
2. 云端列表503时仍可加入本机旅行，重载后地点仍在。
3. 真实写入后丢响应：核对和重试始终使用首次版本；无POI标识也不重复。
4. 首次读取目标旅行时确认换景点，迟到读取不继续POST。
5. POST已发后确认离开，后台可完成，但旧成功不显示在新景点。
6. 不完整200保留原尝试，不冒充成功。
7. 另一标签换号后旧弹窗不发新增，显式同步后只列新账号旅行。
8. 评论输入/评分的离开和刷新取消保留；确认换景点才清除。
9. 收藏显式状态已保存但响应丢失时保留原尝试，读取真实状态后恢复按钮。
10. 评论已提交后丢响应保留原次发布；核对列表不自动重发，取消放弃仍只读。

原生confirm/beforeunload实际触发。503、不完整成功为受控注入；丢响应先向真实后端提交再中断浏览器响应。路由复用使用运行中应用的实际Vue Router，游客夹具调用实际guestTrips存储接口，不替换产品逻辑。collection-success.png与collection-unknown.png由完整套件生成，已观察本轮桌面/手机截图，原生弹窗及核对入口可见，无横向溢出。

## 行为及边界

加入前固定目标、地点快照和读到的版本。结果未知时选择锁定，继续沿用同一快照；核对最新清单仅更新展示，不提升提交版本。现有服务端/本机原子版本检查拒绝陈旧重试，不自动另加一条。这是固定版本防重复，不是新的服务端UUID幂等协议。信息只在本页内存，明确关闭/离开/换号后会丢失，已发写入不会撤销；确认放弃后另起尝试仍需自行核对原清单。

加入保存和核对锁定弹窗关闭，读取列表时可Esc关闭。卸载/换景点/换号使旧读取不能继续写入，旧写入结果不改新页忙碌或成功状态。父页面统一草稿保护，涵盖评论/评分、加入尝试及收藏/评论进行中与未知状态。

收藏现已使用显式目标状态和版本PUT，评论使用服务端UUID去重及按账号/景点隔离的本标签提交快照；未知后可以继续同次操作，核对不清评论输入或原标识。用户明确放弃评论只清快照，不删除已发布内容，之后新建尝试仍需自行核对。新增24项及后端可靠写入证据见`../spot-writes/README.md`。本套不持久化未发输入，不代替真实服务或生产部署验收。跨标签换号测试须等待显式同步完成及详情重新出现，再打开新账号的旅行选择，不能在同步尚未完成时点击即将卸载的旧组件。

组件逻辑测试spotCollectionComponent.test.js共九子场景+父测试计10项，覆盖关闭/卸载、固定快照、旧结果与新忙碌状态、非法目标/响应、本机成功、父页草稿和迟到评论收藏。不渲染DOM，原生交互以上述端到端为准。
