# 个人中心草稿、独立恢复与资料版本

frontend目录运行`npm run test:e2e:profile`。使用真实FastAPI、临时磁盘SQLite、随机JWT、独立Edge与合成账号，阻止非本机请求。桌面1280×900、手机视口390×844各十二项，共24项；不等于真实手机或生产账号验收。

本套件与accounts/guide-editor/sharing/network/creation共享5264及18963，必须串行。Python默认使用工作区上级`.venv-analysis`，可设置TRAVEL_E2E_PYTHON。输出在Git忽略的`playwright-results/profile`，可能含合成凭证，不发布。

## 页面证据

1. 昵称离开取消保留；空收藏的列表入口使用/travel/子路径及路由草稿确认。
2. 刷新取消保留输入，确认后重载云端昵称。
3. 退出取消保留，确认后清除个人资料及输入。
4. 收藏、攻略独立503与重试，不重新读取资料或清除昵称草稿。
5. 资料首次503时仍能查看已有攻略，重试只恢复资料区域。
6. 保存期间禁用输入和重复操作；真实保存一次，卡片/导航同步，成功离开不弹草稿确认。
7. 后端已提交后丢失响应：保留输入；核对后仍用原版本重试，409不覆盖；确认重载才采用云端。
8. 同账号两标签并发编辑：另一页已保存后旧页409，保留草稿；明确载入新版本后可继续编辑。
9. 已提交但浏览器收到不完整200，不冒充成功，不清输入。
10. 旧服务资料缺版本或专用PATCH不可用时不降级旧保存。
11. 空白昵称客户端拒绝、不发请求；明确422保留输入，修改后手动重试成功。
12. 另一标签换号：保留旧页草稿，不发跨账号写入；同步取消保留，确认后才接受新账号资料。

原生confirm及beforeunload均真实触发。503/422/405、缺版本与不完整JSON为受控注入；丢响应先经真实后端提交再中断响应。saved-profile.png及uncertain-profile.png保存桌面/手机排版证据；没有上传文件或使用个人数据。

## 协议与边界

User新增profile_version，GET `/api/me/profile`输出version。新PATCH `/api/me/profile/edit`必须带加载时version；服务端单条条件UPDATE更新昵称/头像及版本，失配409，无字段混写或旧版本覆盖。旧PATCH `/profile`缺版本428；新前端不回退它，旧服务缺version时不开放编辑。GET资料/收藏/攻略及资料写入均no-store。旧结构列默认1，实际旧库仍须备份后演练。

昵称、基线及待确认保存只在当前页内存；离开/刷新/账号变更有确认，不自动跨刷新恢复未保存输入。结果未知重试使用固定昵称与原版本，不自动重试；核对资料更新卡片但保留输入和原保存版本，确认重新载入才换基线。已提交后丢响应的原版本重试会409，需要核对/重载，不能解释为未保存。

资料、收藏、攻略分别加载、错误、重试与序号保护；列表失败不会藏起编辑器或伪装成空列表。账号或卸载改变后拒绝迟到结果；同账号元数据更新不重置昵称草稿。保存/读取成功同步全局昵称/头像/资料版本，身份恢复及同账号登录合并时拒绝旧资料回退；不改变登录凭证。

组件与合并规则测试在`frontend/test/meComponent.test.js`（九子场景+父测试共十项）和`profileInfo.test.js`（三项）；后端`test_profile_writes.py`三项，另扩展真实重启及旧库副本升级。组件不渲染DOM，完整交互以端到端为准；更复杂网络/设备/生产迁移及整站最终视觉仍待验收。
