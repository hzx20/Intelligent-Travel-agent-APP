# 可靠创建旅行与找回结果

frontend目录运行：

```powershell
npm run test:e2e:creation
```

使用账号套件的真实本机Uvicorn与独立Edge夹具，前端5264/travel/、后端18963，必须与账号/网络套件串行运行。临时磁盘库、随机JWT、合成账号、禁用外部服务；不读取业务库。详见 `../account-sharing/README.md`。

桌面1280×900及手机视口390×844各七项，14项用例：

1. 后端已创建但浏览器响应丢失，继续返回相同旅行；成功后再次打开创建页是空白新表单。
2. 刷新后恢复同次尝试；原旅行已被改名时打开其最新状态，不用旧创建信息覆盖它。
3. 缺少可靠创建能力时不发送创建POST，也不回退旧接口。
4. 能力检查成功但专用接口返回405时保留尝试；服务恢复后继续原标识，只创建一次。
5. 切换账号不显示或提交原账号尝试，切回后可继续原旅行。
6. 模拟sessionStorage配额失败，保留输入且不发送创建POST。
7. 放弃的取消分支保留尝试；确认只清空本页信息，已创建云端旅行仍在。

响应丢失通过先向真实后端提交，再中断浏览器响应制造；404/405和配额故障为受控注入，不代表运行了所有历史服务版本。截图与失败trace在Git忽略的 `playwright-results/creation`。

## 协议与保留范围

登录创建先检查GET `/api/trips/create-capabilities`，再POST `/api/trips/create`，必须带UUID request_id。专用路径避免旧服务器忽略未知字段而执行普通创建；不会降级调用旧POST `/api/trips`。

服务端在同一事务内写旅行、日期和 `trip_creation_requests`，以账号+request_id唯一；同内容重试返回200及当前旅行，新建返回201。同标识改内容409；已删除旅行返回410，不重新创建。ORM删除会清空请求关联，避免SQLite编号复用造成旧请求误指向新旅行。旧POST `/api/trips`仍兼容无标识客户端，但无标识调用没有防重复保证。

客户端先按账号将本次标识和四项创建信息存入本标签的sessionStorage，再发POST；存储失败不创建。结果待确认时信息只读，“继续这次创建”可能找回已有旅行，也可能完成尚未写入的原尝试，不会自动发请求。成功打开后清除本次暂存；放弃只清除暂存，不删除云端旅行。

这不是所有表单的自动保存：未提交输入只有离开/刷新保护；已提交尝试只保证本标签刷新恢复，关闭标签或清除存储后不能保证找回该标识，已创建旅行仍可在账号列表查找。不能据此推断分享链接、其他旧页面或供应商请求都已幂等。

后端验证在 `backend/tests/test_trip_creation.py`，另扩展实际进程重启和旧结构升级演练。本轮没有生产部署，也没有验证实际手机设备或生产账号。
