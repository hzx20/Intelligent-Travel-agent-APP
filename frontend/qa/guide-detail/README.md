## 覆盖的完整页面流程

1. 同一个详情组件切换攻略，迟到读取不能覆盖当前正文。
2. 成功响应编号错误时不显示、不开放删除；重试后恢复正确内容。
3. 画廊上一张/下一张及缩略图可键盘操作，换攻略重置图片位置。
4. 旅行选择使用真实`:modal`原生dialog；Tab/Shift+Tab留在弹窗，Esc关闭恢复入口焦点。
5. 列表读取中可关闭，重开后旧列表不能覆盖新旅行。
6. 公开攻略的部分列表故障不挡住本机旅行；重试恢复账号列表，进入实际正文预览但不自动识别或导入。
7. 草稿攻略只显示有权限的账号旅行，不显示本机旅行。
8. 游客从公开攻略进入本机预览，不请求账号旅行、不自动识别。
9. 实际删除提交后丢响应：保留详情、暂停重复删除/编辑/收集；重新读取404后跳转个人中心攻略标签。恢复链接在手机底部导航之上。
10. 删除503时保留详情，核对后才可再次确认；已知成功正常离开，不额外弹等待确认。
11. 删除等待时退出/离开可取消；明确换攻略后旧成功响应不把新页跳走。
12. 私有草稿退出后清正文和管理权限，再登录才恢复。
13. 其他标签换号后不发旧账号DELETE，显式同步才切身份并清除无权查看的旧正文。

路由复用用正在运行应用导出的真实Vue Router push触发，不替换路由或产品响应逻辑；这是组件复用边界验证。游客旅行通过实际guestTrips存储API建立夹具。图片为本机路由提供的合成绿色SVG，只验证画廊操作和布局，不证明真实图片质量。503、错编号响应等为受控注入；删除丢响应先提交真实后端再中断浏览器响应。没有上传文件或调用外部模型/地图/OCR。

## 行为与边界

GuideToTrip沿用TripEditDialog原生模态，加载中可关闭；账号、攻略编号、草稿可见性或禁用状态变化立即清选择、错误和列表。当前上下文和请求代次一致时才接收结果。公共攻略可选择本机/账号旅行，草稿不读取本机列表；预览本身不产生地点写入。

GuideDetail加载拒绝错编号/缺关键字段响应，读取按账号/路由代次隔离。删除继续使用后端原version+revision检查；等待保护路由、刷新及账号变更，确认离开不取消已经发送的删除。已知成功先清旧正文再导航，不再次提示等待；旧上下文响应不导航、不滚动新页。

断连/5xx或会话不确定时显示待核对、暂停编辑/重复删除/收集，保留当前详情。提示在渲染后滚动至可见位置，恢复链接有底部导航无遮挡断言。重新加载才解除暂停：若仍可读，用户核对新内容再确认删除；若404，不冒充已成功删除，清旧正文并提供返回入口。`/me?tab=guides`直达个人中心攻略标签，不改变昵称草稿保存规则。
