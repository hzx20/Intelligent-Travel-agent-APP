# 分享链接生成的安全重试

在frontend目录运行 `npm run test:e2e:sharing`。默认使用已安装的Edge、真实FastAPI和临时磁盘SQLite，桌面1280×900及手机视口390×844各八项，共16项。只使用合成账号，阻止非本机请求，不使用生产数据库或外部服务。手机视口不等于实际手机验收。

此套件与accounts/network/creation共享5264、18963，必须串行运行；Python默认使用工作区上级`.venv-analysis`，可设置TRAVEL_E2E_PYTHON。日志、截图和失败trace写入Git忽略的`playwright-results/sharing`，可能含合成凭证，不应发布。

## 覆盖

1. 准备响应丢失：不产生有效链接，重新准备后仅创建一条。
2. 只读链接实际创建后丢失响应：同页继续返回相同地址，不重复写入。
3. 编辑邀请同样重试，准备凭证及分享令牌均不写入localStorage/sessionStorage。
4. 未知结果中的链接被撤销后继续被拒绝；放弃的取消/确认分支只影响本页，不撤销或复活云端链接。
5. 刷新确认后清除地址及准备信息，管理列表仍可核对原链接。
6. 准备接口404：不降级调用旧的普通创建接口。
7. 激活接口405：保留原准备信息，恢复后继续，不重新准备。
8. 后端已提交而浏览器收到不完整的200响应：保留原尝试，继续后找回同一条链接。

丢失响应由Playwright先提交真实后端再中断浏览器响应制造；404/405及不完整JSON为受控注入，未运行所有历史服务器版本。

## 协议和保留范围

所有者先POST `/api/trips/{id}/sharing/links/prepare`，取得随机43字符令牌及签名准备凭证，此时不落库、不授予任何访问权。再POST同路径下`/activate`，仅提交准备凭证。签名绑定账号、旅行、用途、有效天数与令牌；使用从JWT_SECRET经独立用途HMAC派生的密钥、固定HS256及独立audience，不能作为登录凭证。

首次激活201；同准备凭证并发/重试通过数据库唯一令牌哈希返回200及原地址、原到期时间，不延长有效期。未使用的准备凭证15分钟后410；已经激活的链接在自身仍有效时可在15分钟后找回。已撤销/过期链接409，不重新激活。先验签再检查已存在记录；只对不存在的记录判断准备期限。

数据库仍只保存令牌哈希和管理元数据，无新表，也不保存准备凭证。前端只在当前页面内存保留凭证和地址，结果校验完整后才显示地址；刷新、离开或明确放弃会丢失重试信息。离开/刷新/账号变化沿用父页面草稿保护。地址使用URL片段，读取/接受通过请求正文发送，不放查询参数。管理列表不能找回地址，可核对状态并撤销。

需要稳定且各进程一致的JWT_SECRET（或原有回退密钥文件）。签名密钥轮换后旧准备凭证失效，应核对管理列表，不自动新建；现有哈希链接不因签名密钥轮换本身失效。旧POST `/sharing/links`保留兼容，未提供这一重试保证，新前端不会回退调用它。

后端验证见`tests/test_share_creation.py`及`test_service_restart.py`。此证据不替代生产账号、实际设备、生产代理/日志与多进程部署验收。
