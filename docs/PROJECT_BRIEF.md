# 一、项目介绍

## 1.1 项目概述

在已完成"AI 行程对话助手"（能追问需求、生成行程草稿，已通过测试）的基础上，升级为一个**完整的中文旅行规划平台**，共六大板块：

| 板块 | 面向 | 一句话说明 |
|---|---|---|
| 首页 | 所有人 | 轮播图 + 多个景区推荐 + "猜你喜欢" |
| 旅游景点 | 所有人 | 搜索/筛选景点 → 列表 → 详情（含票价、数据来源、收藏、评论） |
| 线路规划助手 | 所有人 | 整合现有 AI 助手：对话式规划 → 高德地图按顺序标点连线 → 行程单页内直接展示 → 多方案保存与切换对比 |
| 旅游攻略 | 登录用户 | 攻略详情（图文）、自己编写并发布攻略 |
| 个人中心 | 登录用户 | 收藏（景区/攻略两类）、我发布的攻略、基本信息 |
| 管理员后台 | 管理员 | 账密登录，管理用户/景点/收藏/评论/攻略/攻略图片/攻略关联景点/AI 使用记录 |

**延续既定决策**：自己 + 身边人先用、跑在自己电脑上、零成本起步（免费额度）、AI 大模型用智谱 GLM-4-Flash、地图天气用高德。

## 1.2 技术栈（每项附大白话解释）

| 层 | 选型 | 是什么/为什么 |
|---|---|---|
| 前端界面 | Vue 3 + Vite | 目前最主流的网页搭建组合之一：Vue 负责"页面长什么样"，Vite 负责"开发时秒开、发布时打包" |
| 页面跳转 | Vue Router + Pinia | Vue Router 管理页面切换；Pinia 管理页面之间共享的数据（如登录状态、收藏列表） |
| 地图呈现 | 高德 JS API 2.0 | 在网页上画真实地图、按顺序标数字点连线（你的核心需求） |
| 后端服务 | Python + FastAPI | 服务器程序，负责接收页面请求、查数据库、调 AI；FastAPI 是当下 Python 世界最热门的接口框架，自带可交互的接口文档页 |
| AI 能力 | LangChain + 智谱 GLM-4-Flash（已调通） | LangChain 是连接大模型的"万能插座"主流方案：换模型、加记忆、加工具都不用重写代码；底层仍走智谱免费额度 |
| 数据库 | SQLite + SQLAlchemy 2.0 | 单文件数据库**零安装零配置**，数据存在一个 .db 文件里；SQLAlchemy 是 Python 官方生态最主流的数据库操作库，将来想换更强数据库只改一行配置 |
| 缓存/会话 | JWT + cachetools（进程内缓存） | 本机无 Docker 跑不了 Redis 的临时替代：JWT 管登录手环，cachetools 管短期缓存；**上云部署时无缝升级 Redis**，代码接口已预留 |
| 地图/天气数据 | 高德开放平台（已调通） | POI 搜索、路线规划、天气，免费额度 |
| 接口测试 | pytest | Python 世界事实标准的测试工具，现有 M1/M2 测试已全部迁移 |
| 运行形态 | 本机一键启动（前端+后端两个命令拉起） | 浏览器打开 localhost 即用；想给朋友用再补公网部署 |

## 1.3 核心功能模块总览（对应上面六板块，展开关键点）

1. **首页**：顶部轮播图（自动取热门景区图，后台可配置列为可选增强）；推荐景区卡片网格；"猜你喜欢"（v1 简单规则：按收藏热度 + 你收藏过的景区标签偏好推荐，不搞复杂算法），**带分页**（页码 1/2/3 + 下一页按钮，每页 12 条 = 4 列 × 3 行铺满网格，样式与景点列表页分页一致）。
2. **旅游景点**：搜索框（关键词匹配景点名/标签/区域）+ 城市下拉框 + 门票下拉框（收费/免费）；结果卡片含场景图、名称、具体位置、简介，**列表分页每页 12 条**（3 列 × 4 行，页码/下一页真实切换，混多城时卡片标注城市名）；详情页含基本信息、票价、**数据来源标注**（如"高德地图开放平台"）、收藏按钮、评论区。
3. **线路规划助手**：保留现有对话式规划（追问→生成，**流式输出打字机效果**，基于 LangGraph 多节点智能体编排）；打开页面即直接展示完整行程单（按天说明，无需导出文件）；结果页 = 高德地图（数字标点 1,2,3… 按游览顺序连线，点标点弹图片+介绍）+ 地图下方全部景区信息列表 + 行程单说明区 + 本次规划涉及景区卡片（与首页推荐卡同样式，点击直达详情）；支持保存多套规划方案并在方案间自由切换对比；AI 生成的每个地点先经地图接口核实（查无此地自动替换）。
4. **旅游攻略**：攻略列表 → 详情（**两大区块**：顶部图片画廊区——主图 + 左右箭头轮播 + 缩略图切换，可展示多张图；下方正文区——纯文本内容，图文分离、互不重叠）；登录用户可编写发布（富文本/图床上传到本地文件，独立的照片上传入口支持多张）。
5. **个人中心**：我的收藏（景区 tab / 攻略 tab）、我发布的攻略、用户信息（昵称可改、注册时间、收藏统计）。
6. **管理员后台**：独立登录页（账密）→ 8 个管理模块：用户、旅游景点（增删改查+图片）、景点收藏（查看/删除）、景点评论（审核删除）、旅游攻略、攻略图片、攻略关联景点、AI 智能体历史使用记录（展示**总结整理后**的会话摘要，不堆原始聊天）。

## 2.4 数据库配置与表结构（SQLite 单文件 `data/platform.db`）

| 表 | 用途 | 关键字段 |
|---|---|---|
| users | 用户/管理员 | 用户名、密码哈希、昵称、角色(user/admin)、注册时间 |
| scenic_spots | 景点库 | 名称、城市、经纬度、地址、标签、门票类型(免费/收费)、票价、简介、图片(JSON)、**数据来源** |
| favorites | 收藏 | 用户、目标(景点/攻略)、类型、时间 |
| comments | 景点评论 | 用户、景点、内容、时间 |
| strategies | 旅游攻略 | 作者、标题、正文、封面、发布时间 |
| strategy_images | 攻略图片 | 攻略、图片路径 |
| strategy_spots | 攻略关联景点 | 攻略、景点 |
| ai_sessions + ai_messages | AI 会话 | 会话标题、状态、**摘要**（供后台"总结整理"展示）、消息记录 |
| plan_routes | 规划结果 | 会话、需求 JSON、行程 JSON（含标点经纬度） |

- 管理员账号：首次初始化脚本自动创建（随机初始密码，我交付时告诉你，可改）。
- 数据备份：`.db` 文件复制即备份；进 Git 前排除（数据不入代码库）。

# 四、3 个关键决策（2026-09-06 你已拍板 ✅）

1. **游客权限** ✅：游客可浏览首页/景点/攻略，登录后才能收藏、评论、发攻略、保存规划历史——不用强制注册就能逛，转化轻。
2. **景点数据范围** ✅：首批做 **5 个热门城市**（成都、杭州、西安、北京、三亚）约 3000-5000 条，验证跑通后再扩到更多城市——避免一上来拉几十万条把免费配额和磁盘占满。
3. **景区图片来源** ✅：用高德 POI 自带图片字段 + 无图时本地占位图，不另找图源——零成本、来源统一标注"高德地图开放平台"。
