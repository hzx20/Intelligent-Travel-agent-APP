# 一、项目介绍

## 1.1 项目概述

在已完成"AI 行程对话助手"（能追问需求、生成行程草稿，已通过测试）的基础上，升级为一个**完整的中文旅行规划平台**，共六大板块：

| 板块 | 面向 | 一句话说明 |
|---|---|---|
| 首页 | 所有人 | 轮播图 + 多个景区推荐 + "猜你喜欢" |
| 旅游景点 | 所有人 | 搜索/筛选景点 → 列表 → 详情（含票价、数据来源、收藏、评论） |
| 线路规划助手 | 所有人 | 整合现有 AI 助手：对话式规划 → 高德地图按顺序标点连线 → 最近规划/历史对话可回看 |
| 旅游攻略 | 登录用户 | 攻略详情（图文）、自己编写并发布攻略 |
| 个人中心 | 登录用户 | 收藏（景区/攻略两类）、我发布的攻略、基本信息 |
| 管理员后台 | 管理员 | 账密登录，管理用户/景点/收藏/评论/攻略/攻略图片/攻略关联景点/AI 使用记录 |

**延续既定决策**：自己 + 身边人先用、跑在自己电脑上、零成本起步（免费额度）、AI 大模型用智谱 GLM-4-Flash、地图天气用高德。

## 1.2 技术栈（每项附大白话解释）

| 层 | 选型 | 是什么/为什么 |
|---|---|---|
| 前端界面 | React 18 + Vite | 目前最主流的网页搭建组合：React 负责"页面长什么样"，Vite 负责"开发时秒开、发布时打包" |
| 页面跳转 | React Router | 管理首页/景点/攻略等页面之间的切换 |
| 地图呈现 | 高德 JS API 2.0 | 在网页上画真实地图、按顺序标数字点连线（你的核心需求） |
| 后端服务 | Node.js + Express | 服务器程序，负责接收页面请求、查数据库、调 AI |
| 数据库 | SQLite（better-sqlite3 驱动） | 单文件数据库，**零安装零配置**，数据存在一个 .db 文件里；个人平台规模完全够用 |
| 登录认证 | JWT + bcrypt | JWT = 登录后发一张"电子手环"，后续请求凭手环识别身份；bcrypt = 密码加密存储，连管理员也看不到你的原密码 |
| AI 能力 | 智谱 GLM-4-Flash（已调通） | 行程对话生成 + 攻略辅助，免费额度 |
| 地图/天气数据 | 高德开放平台（已调通） | POI 搜索、路线规划、天气，免费额度 |
| 运行形态 | 本机一键启动（前端+后端一个命令拉起） | 浏览器打开 localhost 即用；想给朋友用再补公网部署 |

## 1.3 核心功能模块总览（对应上面六板块，展开关键点）

1. **首页**：顶部轮播图（自动取热门景区图，后台可配置列为可选增强）；推荐景区卡片网格；"猜你喜欢"（v1 简单规则：按收藏热度 + 你收藏过的景区标签偏好推荐，不搞复杂算法）。
2. **旅游景点**：搜索框（关键词匹配景点名/标签/区域）+ 城市下拉框 + 门票下拉框（收费/免费）；结果卡片含场景图、名称、具体位置、简介；详情页含基本信息、票价、**数据来源标注**（如"高德地图开放平台"）、收藏按钮、评论区。
3. **线路规划助手**：保留现有对话式规划（追问→生成）；新增"最近规划"列表与历史对话回看；结果页 = 高德地图（数字标点 1,2,3… 按游览顺序连线，点标点弹图片+介绍）+ 地图下方全部景区信息列表；AI 生成的每个地点先经地图接口核实（查无此地自动替换）。
4. **旅游攻略**：攻略列表 → 详情（文本+图片）；登录用户可编写发布（富文本/图床上传到本地文件）。
5. **个人中心**：我的收藏（景区 tab / 攻略 tab）、我发布的攻略、用户信息（昵称可改、注册时间、收藏统计）。
6. **管理员后台**：独立登录页（账密）→ 8 个管理模块：用户、旅游景点（增删改查+图片）、景点收藏（查看/删除）、景点评论（审核删除）、旅游攻略、攻略图片、攻略关联景点、AI 智能体历史使用记录（展示**总结整理后**的会话摘要，不堆原始聊天）。

# 二、项目构建

## 2.1 环境搭建（你已具备，无需额外操作）

| 项 | 要求 | 你的现状 |
|---|---|---|
| 操作系统 | Windows 10/11 | ✅ Windows |
| Node.js | ≥ 18（建议 22） | ✅ 已装 Node 22 |
| npm 镜像 | npmmirror 加速 | ✅ 已配置 |
| 数据库软件 | **无需安装**（SQLite 是文件） | ✅ 零负担 |
| API 钥匙 | 智谱 + 高德 | ✅ 已调通，存 .env |

## 2.2 系统要求

- 内存 ≥ 8GB（跑前端开发服务 + 后端 + 浏览器）
- 磁盘预留 ≥ 2GB（依赖 + 景点图片库）
- 浏览器：Chrome / Edge 最新版

## 2.3 安装依赖（开发时我来执行，仅列出清单）

```
前端：react, react-dom, react-router-dom, @amap/amap-jsapi-loader（高德地图加载器）
后端：express, better-sqlite3, bcryptjs, jsonwebtoken, cors, multer（图片上传）
```

## 2.4 数据库配置与表结构（SQLite 单文件 `data/platform.db`）

| 表 | 用途 | 关键字段 |
|---|---|---|
| users | 用户/管理员 | 用户名、密码哈希、昵称、角色(user/admin)、注册时间 |
| scenic_spots | 景点库 | 名称、城市、经纬度、地址、标签、门票类型(免费/收费)、票价、简介、图片(JSON)、**数据来源** |
| favorites | 收藏 | 用户、目标(景点/攻略)、类型、时间 |
| comments | 景点评论 | 用户、景点、内容、时间 |
| strategies | 旅游攻略 | 作者、标题、正文、封面、发布时间 |
| strategy_images | 攻略图片 | 攻略、图片路径 |
| strategy_spots | 攻略关联景点 | 攻略、景点 |
| ai_sessions + ai_messages | AI 会话 | 会话标题、状态、**摘要**（供后台"总结整理"展示）、消息记录 |
| plan_routes | 规划结果 | 会话、需求 JSON、行程 JSON（含标点经纬度） |

- 管理员账号：首次初始化脚本自动创建（随机初始密码，我交付时告诉你，可改）。
- 数据备份：`.db` 文件复制即备份；进 Git 前排除（数据不入代码库）。

# 四、需要你确认的 3 个决策（附推荐）

1. **游客权限**：推荐"游客可浏览首页/景点/攻略，登录后才能收藏、评论、发攻略、保存规划历史"——不用强制注册就能逛，转化轻。（备选：全站强制登录）
2. **景点数据范围**：推荐首批做 **5 个热门城市**（如成都、杭州、西安、北京、三亚）约 3000-5000 条，验证跑通后再扩到更多城市——避免一上来拉几十万条把免费配额和磁盘占满。（备选：一次拉 20 城）
3. **景区图片来源**：推荐用高德 POI 自带图片字段 + 无图时本地占位图，不另找图源——零成本、来源统一标注"高德地图开放平台"。（备选：再接其他免费图源，多一份维护）
