2026-11-19，Asia/Shanghai。验证了让独立 nginx 负责旅行站点的 443、现有 `continew-web` 继续负责共享 80 的可行性。已把公网 IP 用作隔离测试的证书身份，没有选择它作为正式入口，也没有开启端口、申请公开证书或切换服务。

## 停止点和后续

正式地址待确认。独立代理可以避免为新增 443 而重建共享容器，但仍需为 443 取得明确部署授权，并审阅以下前提：

1. 保留专用私网地址给新代理，现场核对网络占用、宿主网桥和 8000 的访问边界。当前服务计划仍信任原共享代理地址，须按最终私网地址重新生成规则、仅信任该代理，并验收真实来源和协议头；本轮合成 upstream 不能代替该门槛。
2. 按选定地址准备受信任的证书、续期和到期告警。证书目录独立于静态站和 ACME 挑战目录。续期先验证新证书和配置，再让独立 nginx 载入；不为轮换重启共享容器，也不把签发账户整套密钥放入代理。生产伴随配置涉及只读单文件挂载，按[原挂载切换手册](../deploy/RELEASE_RUNBOOK.md)核对文件和加载行为。
3. 先把新代理保持在 HTTPS 维护状态，验证外部 443 的证书与地址匹配、共享首页仍可用，再按批准的维护流程执行。HTTP 跳转只能在 HTTPS 链路确认可用之后生效；出现故障时保持维护，不能把真实账号退回明文。最终账号、桌面及真实 Android/iOS、现场链路、正式备份和切换仍待验收。

本轮只完成入口方案的隔离验证及归档。实际 Docker 网络、证书、端口和线上服务未改，`production_ready=false`。
