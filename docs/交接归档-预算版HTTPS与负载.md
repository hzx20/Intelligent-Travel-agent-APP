## 停止点与续做顺序

1. 确认计划承载 `/travel/` 的正式地址与 TLS 终止位置。可以使用已有受控域名，或先审查计划使用的其他地址和证书。暂不更改 DNS、申请证书或变更共享 nginx。确定入口后，校验域名/证书链、不绕过证书验证，检查 HTTP 跳转是否保持 `/travel/` 子路径与查询参数、同机另一站点是否保持现状，以及私有路由是否禁止缓存。
2. 从修正后的唯一文件差异在 Linux 原生重建，核对应用/前端编号并更新计划绑定。在带真实部署路径与同等资源约束的隔离环境跑有硬上限的合成读取、写入和 SSE 测试，记录 CPU、内存、错误率、延迟以及未触发供应商。临时证书和本机读数不可代替这一步。不向线上 HTTP 发合成负载。
3. HTTPS 入口确认后再用专用测试账号和实际桌面、Android/iOS 设备验证登录、旅行深链与刷新、两账户权限、预算保存与冲突、弱网恢复。昨日的桌面/手机视口及本轮双合成账号不等于物理设备/真实入口通过。证据保存浏览器、系统与候选版本、预期和结果；不记录密码或令牌。
4. 在新的明确授权下审阅维护窗口、可取回的正式备份、权限调整、正式切换和写入门禁。此轮未动生产、未做实际生产负载、未完成实际设备验收，`production_ready=false`。真实酒店交易、OCR、授权攻略等仍在[阶段验收矩阵](阶段验收矩阵.md)中跟踪。
