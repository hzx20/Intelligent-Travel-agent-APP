# 酒店真实房态、价格和下单：接入方案

2026-11-17，Asia/Shanghai。用户已明确当前范围：**酒店需要真实房态、实时报价和订房；交通先使用高德路线查询。** 用户目前只有高德地图key，没有其他酒店交易渠道或商务交易API文档。交通票务、机票/火车票/租车订单不作为本期新增交易内容。

## 现有能力与缺口

高德已用于真实地点搜索、底图及游客步行/驾车验收。其公开[POI搜索文档](https://lbs.amap.com/api/webservice/guide/api/search/)描述地点检索，酒店相关旧hotel_ordering字段还标为逐渐废弃。不能凭这个字段或POI的消费参考值，认定有指定日期的可售房量、房型或可成交报价。

当前代码的住宿推荐展示地点、评分、距离及外站链接，手动预订记录明确不创建/取消实际订单。本轮核对发现页面没有把高德cost显示为实时每晚房价；这些现有能力继续保留，但真实订房目标尚未实现。

## 可审阅的官方交易渠道

| 方案 | 官方文档已提供的能力 | 本项目仍缺的条件 |
|---|---|---|
| 同程旅仓原生酒店API | [实时酒店详情](https://open.lvcang.cn/doc/api/hotel/apiList/detail.html)包含酒店/房型、库存和价格；[数据验证](https://open.lvcang.cn/doc/api/hotel/apiList/validate)区分产品无效、房量不足和价格不符；另有创单、支付、订单详情及取消接口 | 渠道开通与接口授权、实际账号/签名协议版本、测试环境、结算/支付方式、订单通知设置 |
| 艺龙原生酒店API | [实时搜索流程](https://open.elong.com/doc/info/cn-main-branch-search)衔接查询、创建、支付、订单增量与取消；[创建订单](https://open.elong.com/doc/info/cn-api-meta-hotel_order_create)使用合作方订单号，同次请求复用该号 | 对应API账号及测试权限、当前协议版本、结算与可售产品范围、通知/状态同步方式 |
| 同程旅仓H5嵌入 | [H5文档](https://open.lvcang.cn/doc/api/h5/readme)给出酒店页/订单页及授权交互，并列出合作方需对接的支付、退款和状态回调 | 仍需要渠道授权，不能拿高德key直接拼接成可用交易链接；还需完成订单状态与金额的核对 |

以上是技术接入选项，不表示本项目已经获得权限、确定价格/分成、完成注册或签约。公开文档能阅读不等于账号能交易。Trip.com/PMS或酒店向OTA推房的直连方案，不应未经确认就当作本项目向游客销售酒店的采购接口。

优先按用户最终开通的原生酒店API实现站内体验，保持旅行工作区的一致性；若合作方仅开放H5，则在确认授权和订单/支付衔接后再采用H5。没有真实渠道前不生成虚假房量、价格或订单号。

## 用户流程与实现顺序

1. **输入入住条件。** 从旅行日期预填入住/离店，用户可修改房间数和入住人数；展示供应商真实酒店搜索结果。高德地图只用于位置展示与周边参考，供应商hotel_id、room_type_id和rate_plan_id单独保存，不能用同名酒店或amap_id直接替代。
2. **选择真实房型与报价。** 按供应商响应展示每晚价、总价、币种、税费、餐食及取消规则；缺少的字段明确不作保证。服务端保存报价快照及其日期/人数/房数/房型/版本。报价查询本身不宣称锁房。
3. **提交前复核。** 用户选择房型后调用供应商验价验房。若价格、库存或规则变化，展示新结果并重新确认，不静默使用旧报价提交。具体有效期和是否锁房按实际渠道契约处理。
4. **用户确认后创单。** 本地先持久化一次订房尝试和不可变请求摘要，再使用固定合作方订单号请求渠道。创建失败、超时或回执丢失时先查单；不换编号重发制造重复订单。艺龙公开文档要求同次创建复用AffiliateConfirmationId，重发间隔规则需按开通的实际版本执行，不凭HTTP超时立即自动重试。
5. **处理支付与确认。** 创建成功、付款成功、酒店确认分别记录，HTTP200或收到订单号不能直接显示“酒店已确认”。采用渠道支持的现付/担保/预付及结算方式；使用认可的支付通道，不在旅行手动记录里保存支付凭证。订单中间态可刷新和恢复查询。
6. **同步订单状态。** 收到通知后验证身份、记录事件并核对订单详情，重复或乱序事件不倒退状态。具体接口与重试期限按渠道文档实现。[旅仓H5指引](https://open.lvcang.cn/doc/api/h5/readme)建议通知后再查详情，关键状态/金额以详情为准；[艺龙流程](https://open.elong.com/doc/info/cn-main-branch-search)列有订单增量同步。
7. **取消和售后。** 先展示渠道返回的可取消状态、时间和费用，用户确认后申请取消，再核对终态。申请已收、取消中、已取消和退款结果分别处理，不把本机状态编辑当作渠道取消成功。

账号与数据设计：新增真实订单实体，与已有手动预订记录区分；订单属于付款/预订账号，并可关联旅行安排。不能继承“同行编辑者可以改手动记录”就允许同行者支付或取消真实订单。只读分享不公开入住人、联系方式、支付信息或订单访问凭证。安排删除或移动不自动变更实际酒店订单。

## 接入开工所需信息

当前需要先开通一家酒店交易渠道的测试权限。收到以下信息后再编写具体渠道适配器和联调：渠道产品名称、当前API文档版本、测试API入口、已获批的查询/验价/创建/查单/取消权限、账号的安全配置方式、结算方式及订单状态通知要求。密钥不发在聊天或代码中；具体注入位置在真实渠道确定后配置。

### 测试权限申请

2026-11-25 核对了两家的公开接入信息。可以先向艺龙开放平台询问站内酒店预订的合作条件，其[合作指南](https://open.elong.com/doc/info/plat-guide-cooperation_branch)列出了酒店商务邮箱 `fxswb@ly.com`。[接口公共协议](https://open.elong.com/doc/info/cn-main-api_list-common_params?menuName=%E6%8E%A5%E5%8F%A3%E5%85%AC%E5%85%B1%E5%8D%8F%E8%AE%AE)列出的测试动态接口域名为 `api-test.elong.com`，测试与生产使用独立账号，测试动态接口也需要登记调用方 IP。是否接受个人或当前项目主体、资质门槛和费用需由商务确认。

如选择同程旅仓，向其商务侧申请分销账号与酒店交易权限。[官方接入指南](https://open.lvcang.cn/doc/api/agent/skill)列出了 `x-lvcang-api-account` 和 `aesKey` 两项开户凭据。测试入口、测试商品、可执行的交易操作和结算方式以开通回执为准。

申请时可说明项目是 Web 旅行规划应用，需要在站内展示实时房态、价格与取消规则，并完成酒店预订、查单及取消。请渠道确认支持的合作主体、可售区域、可用测试酒店、试单与创单权限、支付或结算方式、订单状态同步，以及测试单是否产生真实库存占用或费用。

开通后只需告知所选渠道、已开通的测试权限和非秘密文档。账号密钥通过后端安全配置录入。本次核对限于公开资料，渠道申请待提交。

## 必须取得的验收证据

先在渠道测试环境走通真实查询→验价→创单→查单/支付状态→确认/取消；覆盖价格变化、库存不足、回执丢失后同次核对、刷新/重启恢复以及通知重复/乱序。真实渠道返回值与页面展示逐项对应，不能以模拟接口通过替代真实房态及下单完成。

测试环境全链通过并形成具体、可审阅的订单/金额/恢复方案后，才安排生产联调。普通开发授权不代表现在提交会产生费用的真实预订；当前未发起真实订单、支付或取消。

酒店交易当前停在申请渠道测试权限。公共攻略候选、共享缓存及其他发布事项见[交接归档](./交接归档-攻略图片导入恢复.md)。
