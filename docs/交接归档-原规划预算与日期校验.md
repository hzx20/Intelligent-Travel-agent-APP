## 为什么不能宣称复杂方案已通过

原始复验result.json的passed仅表示该脚本的数字/形状检查；人工语义复核另存semantic-review.json，完整场景为false。保留两种记录，不篡改已取得结果。

仍有具体缺口：

1. 每天出现“附近餐馆”，最后还有“酒店”等占位名称，不能视为已识别具体POI；本轮未调用高德，不宣称地点核实已完成。
2. 第二天把“杭州动物园”标为“室内场馆”，缺乏可信依据；不能凭模型自己给出的类型判定满足室内偏好。
3. 12项中未提供明确休息活动，与每日保留休息的要求尚未对应。
4. 三个被模型标为室内场馆的条目各写50元cost_estimate，但门票分项仅50；分项与总计通过不等于逐条费用已核对。
5. 宋城等地点的零元/估计费用和酒店区间均无实时报价证明，不能证明预算可成交、房态可售或订单可下。

因此，本轮只关闭预算分项/合计/数值上限与日期编号的校验缺口，不关闭原规划器完整复杂场景。后续应先处理占位地点核实与偏好/逐项费用的一致性，再做完整复验；不要重复消费相同样例只是为了得到绿色记录。

校验边界也保留：只有总计的兼容简化回复无分项可核对；无明确数字预算且无汇总时不虚构数值；描述性预算文本不猜测硬上限。金额仍是AI估算，不是实际价格保证。
