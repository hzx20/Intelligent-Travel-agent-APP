# 智能旅行规划 Agent

2026 年 11 月 26 日版本已上线，支持中文维基导游链接导入、游客行程复制到账号、足迹照片上传结果核对和共享查询缓存。

一个能"说话就能出路线"的旅游规划网站：输入一句"成都 3 天，带 5 岁孩子，轻松一点"，
AI 追问→生成行程→尝试通过本地 POI 和高德核实地点→附天气预报，
最后展示一张按顺序连线的路线示意图。生成在后台任务中执行，前端轮询进度。

采集脚本首批覆盖 **成都 / 杭州 / 西安 / 北京 / 三亚** 五座城市，景点数据来自高德开放平台 POI；新安装时数据库为空。

## 一、怎么启动（最省事的方式）

已有原作者 WorkBuddy 环境时可双击 `启动网站.bat`。其他环境请按下面的步骤启动。

> 用的时候两个黑窗口要**一直开着**，关掉就等于关网站。

### 手动启动（想自己控制时用）

```powershell
# 在项目根目录（需要 Python 和 Node.js）
python -m venv .venv
.\.venv\Scripts\python -m pip install -r backend\requirements.txt
cd backend
..\.venv\Scripts\python -m uvicorn app.main:app --port 8000

# 另开终端，在 frontend 目录
npm ci
npm run dev
```

后端启动后可访问：
- 接口文档（可在线调试）：http://localhost:8000/docs
- 健康检查：http://localhost:8000/api/health

### 第一次使用要做的一件事

**管理员账号需要手动提权**：先在前台注册一个账号，然后在 `backend` 目录执行：

```bash
..\.venv\Scripts\python tools/make_admin.py 你的用户名
```

提示"已提升为管理员"后，**重新登录**该账号，导航栏就会出现「管理后台」。
（加 `--revoke` 可以收回管理员权限。）

## 二、能做什么

### 我的旅行（新行程编辑器）

- 登录后可创建多日旅行，编辑每天的地点与活动、调整顺序、跨天移动，并从景点库收集待安排地点。
- 已保存的 AI 规划历史可显式转为可编辑旅行，原始历史保留。
- 在行程详情按需查询相邻地点的步行或驾车路线。高德返回的路线和耗时为参考；无坐标或查询失败会明确提示，地图虚线是顺序示意。
- 行程内 AI 助手先展示新增、修改、移动或删除建议，确认后才写入；建议基于生成时的版本，过期后须重新生成。AI 新增地点需要用户核实，可在编辑安排时搜索景点库关联。
- AI 建议依赖已配置的模型服务；当前生成请求尚不支持断线恢复。路线查询依赖高德 Web 服务 key 和对应权限。

### 游客（不登录）
- **首页一句话发起路线规划**（填目的地/天数/偏好 → 自动跳到规划页开跑）
- 浏览首页的热门目的地（点城市直接填回规划入口）与猜你喜欢（8 条精选）
- 景点列表（关键词/城市/门票筛选）、景点详情
- 看所有人发布的旅游攻略
- 用 AI 规划助手出路线（只是不会保存到历史）

### 登录用户（额外）
- 收藏/取消收藏景点、发表评论（1-5 星评分）
- 写攻略、存草稿、编辑、删除（草稿只有自己看得到）
- AI 规划自动存为历史方案，随时切换对比
- 个人中心：改昵称、看我的收藏、看我发布的攻略

### 管理员（额外）
- 六组模块：用户管理（停用/启用、授收管理员）、景点管理（修正采集数据）、
  收藏记录、评论审核（软删）、攻略管理、AI 规划记录
- 模拟酒店渠道库存同步：管理员通过 API 推送按日房态、查询库存和同步记录，支持幂等重试。数据由调用方提供，不连接真实渠道，也不支持预订。操作示例见 [酒店渠道库存同步演示](./docs/hotel-channel-demo.md)。

## 三、技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | FastAPI + SQLAlchemy 2.0 | 换 MySQL 只改连接串，模型零改动 |
| AI 编排 | LangChain + **LangGraph** | 五节点状态图：澄清 → **资料检索** → 生成 → 地图核实 → 天气 |
| 检索增强（RAG） | 智谱 `embedding-3` + SQLite BLOB + numpy | 1708 个知识片段，城市硬过滤 + 向量/关键词混合排序，不引入独立向量库 |
| 大模型 | 智谱 GLM-4-Flash | OpenAI 兼容端点，改 `base_url` 即可换 DeepSeek |
| 数据库 | SQLite（`backend/data/app.db`，已 gitignore） | 单机够用，预留 MySQL |
| 前端 | Vue 3 + vue-router + Vite | 全站 640px 移动端自适应 |
| 地图/天气 | 高德开放平台 | POI 采集、地点核实、天气、静态地图 |

> **关于 Neo4j**：已列入远景待办，不排版本。触发条件是将来要上"智能推荐引擎"或
> 三层以上关系推理——届时只替换 LangGraph 的检索节点，架构不动。

## 五、测试与走查

```powershell
# 离线回归（在 backend 目录，不调用模型；用项目自己的 Python 环境）
python -m pytest tests -q --ignore=tests/test_m1.py --ignore=tests/test_m2.py -k "not test_plan_stream_saves_history_when_logged_in and not test_graph"

# 全链路走查（连真实数据库，不起服务、不走代理，自动清理）
python tools/walkthrough_v10.py
# 加 --with-ai 会额外真实调一次智谱出 3 天行程（约 40 秒）
```

- `tests/` 覆盖：数据底座、收藏评论、个人中心/后台权限、LangGraph 编排、攻略、静态地图、v1.0 边界
- `tools/walkthrough_v10.py`：游客浏览→注册→收藏→评论→写攻略→静态地图→后台六模块→清理，一条龙 51 项
- 前端构建：`frontend` 目录执行 `npm run build:travel`（部署在 `/travel/` 子路径时必须用这个；默认 `npm run build` 会把 base 改成 `/`，发布校验会失败）

> 全量 `pytest tests -q` 包含真实模型调用，会消耗 API 额度并依赖网络；离线回归不验证真实模型输出。

### RAG 检索指标（2026-11-27 实测）

| 项目 | 数值 |
|---|---|
| 语料规模 | 1708 个片段（维基导游 1208 + 景点 500），覆盖 20 个目的地 |
| 向量 | 智谱 `embedding-3`，1024 维 float32（4KB/条，存 SQLite BLOB） |
| 切块 | 400 字/块，重叠 80 字，按行/句边界切分 |
| 开发集 Recall@3 | **0.95**（20 条，写同义词表时对着它调过参数，只能防回归） |
| 留出集 Recall@3 | **0.82**（60 条，写完没再按它调参） |
| 平均检索耗时 | 约 240-270 ms（含 embedding API；网络抖动时单次会到 1 秒以上） |
| 生产参数 | `min_score=0.35`，`Top-K=5`，0.8 向量 + 0.2 关键词 + 意图修正 |

两套评测集要分开看：开发集分数偏乐观，留出集才说明"换一批问法还能不能召回"。留出集 11 条未命中的原因分类如下，**没有一条是排序算法写错**：

| 原因 | 条数 | 例子 |
|---|---|---|
| 语料里就没有这个内容 | 9 | 「厦门哪里吃海鲜」——厦门条目没有餐饮章节；「深圳哪里看海」——观光章节没列大梅沙 |
| 标注过严（返回了合理结果，只是不是我列的景点） | 1 | 「三亚哪个海滩好」返回椰梦长廊、小东海 |
| 切块把关键词分到了别的片段 | 1 | 「成都火锅」——火锅内容在「用餐」章节的另一块里 |

结论是瓶颈在语料覆盖，不在检索算法。下一步该补的是景点描述和真实攻略（`guides` 表现在还是 0 条），不是调权重或加 rerank。

阈值 0.30 / 0.35 / 0.40 × K 3 / 5 / 8 九组组合的 Recall@3 全部为 0.95（开发集），说明当前语料下结果对参数不敏感。排序分 = 0.8 向量 + 0.2 关键词覆盖率 + 意图修正（未问交通时交通章节 -0.05；室内意图 ±0.04）：关键词分负责捞专有名词（洪崖洞、漓江），意图修正负责纠正「少走路却返回公交时刻表」这类向量盲区。

复现命令（在 `backend/` 下）：

```bash
python scripts/ingest_spots.py     # 景点灌库（约 30 秒）
python scripts/ingest_guides.py    # 维基导游灌库（约 2 分钟，需外网）
python scripts/export_knowledge.py --output ../knowledge.jsonl   # 导出给无法访问维基的服务器
python scripts/eval_retrieval.py             # 开发集 Recall@3 + 耗时
python scripts/eval_retrieval.py --set holdout   # 留出集 60 条
python scripts/eval_retrieval.py --sweep     # 阈值 × K 九组对比
```

## 六、环境变量

项目根目录的 `.env`（**已被 gitignore，不会进存档**）：

```
ZHIPU_API_KEY=你的智谱 key
AMAP_API_KEY=你的高德 Web 服务 key
AMAP_JS_KEY=你的高德 JS API key
AMAP_JS_SECURITY_CODE=你的高德 JS 安全密钥
JWT_SECRET=独立的随机长密钥
```

缺少智谱密钥时仍可启动并浏览，AI 规划不可用。高德密钥用于地图及地点数据；新建数据库为空，需配置 Web 服务 key 后在 `backend` 目录运行 `python scripts/fetch_pois.py --all` 采集数据。未配置 `JWT_SECRET` 时会在 `backend/data/.jwt_secret` 生成本机密钥；生产环境应显式配置并妥善保管，修改密钥会使已有登录失效。

规划任务保存在 SQLite，服务重启后可在执行租约过期后恢复一次。已完成任务可找回 30 分钟，登录用户的已保存方案继续保留在历史。恢复可能再次调用模型。游客凭当前标签页保留的不公开任务编号找回。

规划提交有独立的尝试标识。刷新后可在当前标签页继续同一次提交，找回原任务。规划历史保存使用版本校验，删除后提供 8 秒撤销窗口。

首页按来源独立加载旅行。历史方案转换或游客旅行复制遇到网络中断时，可以核对结果或继续同一次操作。转换和复制均保留原件。

## 七、常见问题

**Q：管理员进不去后台？**
A：注册后必须跑一次 `tools/make_admin.py 用户名` 提权，然后**重新登录**。

**Q：地图不能拖动缩放？**
A：动态地图需要配置高德「Web端(JS API)」key 和安全密钥；它们与 Web 服务 key 不同，需另行申请。

**Q：数据库在哪、怎么重置？**
A：`backend/data/app.db`。删掉这个文件，下次启动会自动重建空库（景点数据需重新跑
`scripts/fetch_pois.py` 采集）。

**Q：换城市/加城市？**
A：改 `scripts/fetch_pois.py` 里的城市列表重跑采集即可；前端城市下拉在
`views/SpotsView.vue` 和 `views/GuidesView.vue` 的 `CITIES` 常量里。
